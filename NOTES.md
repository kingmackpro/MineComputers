## Update 2026-11-01: playback polish, shared clock + late joiners (written, NOT compiled, not run)
- **Shared clock:** `MediaTransfer` keeps every playing Speaker sound and Screen video (`Key` = dimension + pos + video, `Active` = file id, volume, loop, start tick of the server game time). `MediaPlay` and `VideoPlay` now carry `positionMs` = how far the playback already is when the packet is sent. The client turns that into `originNanos` (the moment, on its own nanoTime clock, at which the playback was at 0) in `MediaClient.originOf`; video (`VideoPlayer`) and sound (`MediaSoundInstance` -> `FfmpegAudioStream` / `Mp3Stream`) both start at "now - origin" into the file (seek; looping = modulo the file length; past the end of a non-looping file: last picture, silence). So a slow download or sound engine start no longer shifts anything, and a Screen and a Speaker started in the same tick by a script line up. Video drops pictures that are more than 100 ms late (still shows one every 250 ms) to catch up. Loop restarts add the file length to the origin, so there is no drift.
- **Late joiners:** `MediaTransfer.sync(level)` runs once a second (`LevelTickEvent.Post`, registered in `MineComputers`) and right when something starts: every player within 48 blocks of an active Speaker/Screen who was not sent it yet gets the play packet with the current position (and downloads the file if needed: it is announced to him first); a player who goes further than 64 blocks gets a stop (frees his decoder) and is sent it again when he returns (`TOLD` per player). Stop/restart/removal clears the entry; `ServerStoppingEvent` and logout clear the state.
- **Not done / limits:** clocks are server game ticks (50 ms resolution) + one-way network delay is ignored, so expect a few tens of ms difference between players; MP3 seeking skips frames without decoding (can click slightly); a player changing dimension keeps playing what his client had (client keys are positions only); URL playback is still not implemented.
- Test: put a Screen and a Speaker next to the Brain, `get("screen:1").playVideo("media/x.mp4", true); get("speaker:1").playFile("media/x.mp4", 1, true);` (same tick), then (1) watch that picture and sound match, (2) walk away more than 64 blocks and come back: it should join in at the current position, (3) have a second player join later.

## Update 2026-11-01: Remote Gateway + Remote Access (written, NOT compiled, not run)
- **How it works for the player (my design, change it if you want something else):**
  1. Put a **Remote Gateway** block so it touches a Data/Power Data Cable or the Brain (like a placed laptop does).
  2. Right-click the gateway with a **Link Transmitter**: it stores the gateway (dimension + position). Right-click another gateway to re-link it.
  3. **Redesigned (Ralfs): the Laptop item has its own upgrade menu.** Right-click the Laptop item (in the air or on a block) = a menu with 2 slots: **Remote Access** (only that upgrade fits) and **Link Transmitter** (only that fits), plus the inventory. The items stay stored on the laptop stack (vanilla `DataComponents.CONTAINER`, saved on the server on every slot change); the held laptop's slot is locked while the menu is open. Take them out again any time (shift-click works).
  4. The menu shows a status line ("Insert a Remote Access upgrade" / "Insert a Link Transmitter" / "Linked to gateway x, y, z") and an **Open editor** button, enabled when both items are in and the transmitter is linked. The server checks range (50 blocks, same dimension, gateway loaded) when the button is pressed, closes the menu and opens the editor for the system the gateway touches. Messages go to the action bar ("Out of range", ...). The transmitter is NOT used up: it stays in its slot (one gateway per laptop; swap the transmitter to change it).

## Gotchas learned earlier
1. GraalJS is `org.graalvm.polyglot:polyglot` + `org.graalvm.polyglot:js-community`, not the old `org.graalvm.js:js` group.
2. On NeoForge 1.21.8 and below a library must be in both `implementation` and `additionalRuntimeClasspath`, or it compiles but throws `NoClassDefFoundError` at runtime. Already done in `build.gradle.kts`.
3. GraalJS is not yet bundled into the mod jar. Jar-in-jar (so players don't need the library installed) is part of milestone 2.
